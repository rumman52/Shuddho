# CW-18 — Availability SLI and SLO measurement contract

Status: **proposed measurement contract; not observed, not release authorization**. The 99.9% target is not a production claim. This contract fills CW-18 Step 1 and Part 05 §8; approval of endpoint deadlines, collection source and workload is required before measurement.

## Primary availability SLI

Request-based, over one complete rolling 30-day UTC window [start, end). Freeze the release SHA, rollout digest, API/worker build, database/model identity, approved member scope and per-route deadline before collecting the window. Split evidence on material identity/policy changes; never blend another release or silently reset a poor window.

Eligible denominator: every attempt reaching the approved service boundary for an enabled, in-scope user-facing route by an authorized member, within approved quotas and supported request schema. Include eligible requests whose response is lost, times out or cannot reach the application because of DNS/TLS, gateway, server, dependency, database or provider failure; use the approved ingress/client-side observation boundary to detect those failures, not application-success logs alone. Each retry is a separate request. A request is good only if its contractually correct response, including an explicit legitimate needs-input state, arrives before the frozen endpoint deadline. A transport-level 200 hiding an application failure is bad. An accepted 202 is good for admission only if durable admission is confirmed; it is not evidence of completed work.

Excluded, recorded separately: authenticated negative access tests, expected malformed/invalid requests, expected unauthorized/nonmember or revoked access denials, explicit above-contract quota requests, non-user health probes, load-test traffic and user cancellation before the service accepted work. Do not exclude system-imposed overload, capacity errors, unclassified 429s, server/provider failures, planned maintenance or failures hidden by fallback. If classification is uncertain, keep it in a separate unknown bucket and mark the observation incomplete rather than dropping it.

Report exact integers: eligible_good, eligible_bad, each exclusion reason, unknown, missing collection intervals, total observed attempts; reconcile mutually exclusive counts. Availability = eligible_good / (eligible_good + eligible_bad); error fraction = eligible_bad / eligible. Target is 999/1000, compared exactly: 1000 × good >= 999 × eligible. Allowed failed requests = floor(eligible/1000). Zero eligible attempts or incomplete/unreconciled ingress coverage means **not measurable**, not 100%. Example: 999/1000 exactly meets the point target; 998/1000 misses it. Do not imply future reliability from a small cohort. The 43.2-minute figure applies only to a separately defined time-based 30-day SLI, not this request SLI.

Measure per route class and pooled: writing/review, enabled coworker read/admission, owner-authorized artifact access. Freeze the actual route allowlist and deadlines from the exact release with Owner C; disabled capabilities are not added to the denominator. Report eligible counts, p50/p95/p99 end-to-end, status/error class counts, and the window completeness. Also report distinct, non-substitutable SLIs: accepted durable task completion within the frozen workflow deadline, queue wait from admission to first claim, scheduled occurrence timeliness under approved schedule/pause semantics, and restore/recovery RTO/RPO. Cancelled/needs-input/blocked jobs must have explicit outcome accounting; never call them successful deliverables unless the task contract defines that outcome as useful and a reviewer confirms it.

## Evidence and privacy

Use the existing `scripts/core_agent_observability.py` exports for task/model/tool economics and `scripts/cohort_health_gate.py` for health and STOP signals; neither run counts nor health samples prove request availability. Collect request-level measurements only from an independently approved ingress or monitoring source with missing-interval detection. Retain sanitized aggregate counts and provenance: release ID, revision, rollout digest, UTC window, metric/version, route class, status class, counts/latencies, receipt SHA and operator reference. Do not collect prompts, source content, URLs with query strings, account identifiers, raw tokens or personal message contents. The private evidence directory, region, consent, retention and deletion require separate approval; PostHog capture remains disabled until #584 is resolved. A missing source or incomplete coverage blocks any observed SLO claim.

Do not lower mandatory Day 8/9/10 quality, recovery, security or approval thresholds. Availability is not permission to launch; any unauthorized access, duplicate mutation or other safety violation remains independently disqualifying.
