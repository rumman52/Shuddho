If live budget or exact runtime identity is missing, mark this mode blocked.

## Measurements and comparison

Record window, mode, release and rollout digest, offered concurrency, accounts, total submitted/completed/failed/rejected/cancelled, all retries and unknown outcomes, ingress latency p50/p95/p99, task completion p50/p95/p99, queue age/claim delay, CPU, memory, DB connection utilization, provider saturation/failure/unknown usage, tokens, all-in actual cost per attempted and per human-accepted task. Record model and tool errors, max resource utilization, safe drain time, recovery time and restored-state integrity. Preserve raw evidence privately and only export allowlisted operational aggregates. Missing observations are unknown, not zero.

Existing review template reference thresholds (unchanged, not an initial pilot GO): simulated success >=99%, rejection <=1%, submission p95 <=500 ms/p99 <=1 s, completion p95 <=15 s/p99 <=30 s, queue age <=30 s; live success >=95%, rejection <=5%, completion p95 <=120 s/p99 <=180 s, provider failure <=5%, provider p95 <=90 s, average accounted tokens <=20,000/completed task. Use the reviewed exact template/owner-approved limits; any proposed change needs separate review and cannot relax mandatory release thresholds. Report actual numeric limits and results, not generic green labels.

Stop immediately on unauthorized access, mutation, budget violation, unbounded queue growth, secret exposure, corrupted artifacts, duplicate effects, or failed owner/cancellation/rollback boundaries. Preserve failed evidence. After load, operate the existing cohort health gate and verify safe drain and fresh zero-breach status.
