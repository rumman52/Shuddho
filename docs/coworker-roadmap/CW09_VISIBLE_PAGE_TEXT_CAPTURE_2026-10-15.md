# CW-09 — bounded private visible-page-text capture (15 October 2026)

**Base:** `main` `e4a2e671ccaef9ab212f77cbd02521eec9866bd6` (PR #403 merged; its exact PR-head CI passed). **Branch:** `codex/cw09-owned-page-text-capture-20261015`. **Security boundary:** existing default-off Runtime v3 Agent browser command, isolated Playwright worker, broker PostgreSQL transaction and existing TokenVault only.

## Reproduced baseline
The `browser.read` worker returned URL/title/DNS/redirect metadata and hashed JSON of URL/title. Runtime v3 marked this `metadata_only`. No page text entered the trusted broker or owned Agent observation. A title digest is **not** a digest of page content. This fails the work-workflow requirement to read a public page for grounded research.

## Coherent implementation slice
1. Only on server-issued `agent_read_only` navigation, the isolated browser worker extracts the rendered body's visible text using code-owned DOM inspection, bounds it in page and worker process, preserves UTF-8 codepoint boundaries and reports whether a capture was truncated. The extracted text is always untrusted; worker continues to deny cookie continuity, downloads, unsafe network destinations and non-GET/HEAD Agent requests.
2. The strict typed worker evidence adds optional `page_text` (at most 8,192 UTF-8 bytes in the broker) and `page_text_truncated`. Bad shapes, lone surrogates, over-budget bytes, NULs and inconsistent truncation evidence fail through the existing committed terminal Agent receipt rejection. Legacy metadata-only receipts remain supported and truthfully labeled.
3. After the existing worker lease, origin, redirect, DNS and no-interaction checks pass, the broker encrypts the exact captured UTF-8 text using the existing private TokenVault, owner/session/command-bound, in the `BrowserCommand.result` ledger; it records **SHA-256 of exactly those captured UTF-8 bytes**, byte count and truncation flag. Public command DTO and worker completion response **never** contain plaintext or ciphertext. The server-side Agent runtime may read through an owner-bound, non-terminal, non-expired broker getter only.
4. Runtime v3 releases an up-to-1,200-byte UTF-8 *untrusted excerpt* with source URL, true content digest, byte count and truncation in the owner-bound verified tool receipt. The authoritative Agent settlement atomically scrubs the temporary sealed text body, leaving only digest/size in the broker ledger. Browser cancellation and expiry also scrub it. No new schema, storage bucket, activation ledger or release authority.
5. **Limitation explicitly preserved:** this is a bounded visible-text excerpt, **not full HTML bytes or durable source artifact**, and its hash is of the emitted bounded visible-text capture, **not full upstream HTML/HTTP response**. It still needs operated sandbox/network verification, source-versioned private artifact retention when required, prompt-injection evaluation and staging release qualification. Missing page text still yields `metadata_only`, not a fabricated page read.
